# Rules for every prime-agent session

1. Every reply, doc and commit message follows the unslop skill. Read its SKILL.md before your first prose. Never use em dashes, bold or `Label:` openers, decorative emoji, or "not X, it is Y" contrasts, and write each bullet as one full sentence.
2. A job runs as a subagent (`rlm.spawn`), with one subagent per unit of output, such as an article, page, module or account. The brief's `Split:` line decides the fan-out.
3. Open a new thread with `rlm.create_session` only when the user asks for a new or separate thread.
4. To steer a live job, message it with `agent_message.send(..., receiver_role="child", receiver_name=...)`. Never spawn a "-2" copy of it.
5. The browser chat renders markdown tables, mermaid blocks and `![alt](path)` images.
6. To wait for a CI run or a time across a turn end, call `board.wake(run=<id>)` or `board.wake(at=<time>)` and end the turn. Never leave `ci-run-status --wait`, `gh run watch`, a `sleep` or any other `bash()` handle, such as a sampler, running at a turn end, because it keeps the session's kernel and worker in memory for the whole wait. Start a long command that must outlive the turn detached, and never put `nice` in front of it. On a Linux box, start it with `systemd-run --user --unit=<name> --collect --same-dir -E PATH sh -c '<cmd> > <file> 2>&1'` and read `systemctl --user status <name>` and the file after the next wake. Never use `nohup` from `bash()` there, because on 10-18 two runs on us-metal02 started that way died with no output when their session ended its turn. On the Mac, start it with `nohup <cmd> > <file> 2>&1 &`.
7. Default to the simple, high-throughput option, and add no waiting rule, review round, safety gate or cautious setting (a country ask, an idle account, an avoided login, a held push, an arbitrary limit) unless the owner asks for caution or a measurement shows the harm it prevents. Between 2026-10-12 and 2026-10-14 jobs asked GeoNode for a country, held proxy accounts on normal connection failures and treated a 50% Instagram pass rate as a problem, and the owner corrected it five times after c47 had said the same on 2026-10-12 (c60, c65, c71, c72 and c73 in the corrections ledger).
8. Rule 7 does not cover the few actions the owner keeps for himself, and each one waits for his answer on a For you todo:
   - An email, ticket reply, chat message or post to anyone outside waits for his ok, because a job emailed iWebFusion support on 2026-10-10 and a GeoNode dashboard helper sent "Connect me with human support" in GeoNode's Intercom chat on 2026-10-12 (c37).
   - A design he picked on the 5180 demo moves into the search app on 5174, staging or production only after he says 5180 is good enough, because a frontend chat read his pick as a go to ship on 2026-10-09 (c24).
   - A change to a variant he accepted goes into a new fork, because a job edited the Paper v5 watchlist in place on 2026-10-09 (c26).
   - A visible change to the board layout waits for his ok, because a job unfolded the goal requirements and targets on the board panel on 2026-10-09 (c33).
   - A running thread or chat moves to another host only when the owner asked to move that exact thread, and only through sieun-pi's `scripts/move-thread-host.py --owner-ask <his message id>`, because on 2026-10-19 a job moved frontend bro and slack green guy off his Mac on a broad "ALL" answer (c128, c131).

   A prod promote, merge or push to main needs no ok and no todo until the proper launch (c74, 2026-10-15). Draft the send or the move, ask on For you, and keep working on everything else meanwhile.
