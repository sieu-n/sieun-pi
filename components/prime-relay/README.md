# prime-relay

prime-relay is a small HTTP server that runs on every box and exposes that box's Prime daemon socket over the tailnet. It checks a bearer token on every request and knows nothing about sieun-pi, chats or other boxes.

## API

Every request needs `Authorization: Bearer <token>`, and a request without it gets 401.

- `GET /v1/health` returns `{"ok":true,"daemon":"answering"|"down","version":1}`.
- `GET /v1/daemon` with `Connection: Upgrade` and `Upgrade: prime-daemon` answers 101 and then carries raw bytes both ways to the daemon socket, so the JSONL protocol passes through unparsed. Two request headers change what goes back to the client. `x-prime-slim-snapshot: images` empties the image data in every attach snapshot chunk but the last (`slim-snapshot.mjs`). `x-prime-line-delta: 1` sends each `message_update` line after a session's first as copies of the previous update plus the new text (`line-delta.ts`), because the daemon sends the whole partial message with every token. `decodeLineDeltas` in the same file rebuilds the exact bytes, and HostBridge sets both headers. A `prompt` command from the client that carries `ownerTurn: <session id>` reaches the daemon at once without the field while this box's `pi-pool owner-turn` marks that session beside it (`owner-turn.mjs`), so the owner's message skips the turn queue with no extra wait. A `create` command that carries `relayFirstPrompt: {message, ...}` reaches the daemon without the field, and the relay sends that prompt to the new session the moment the create answers, then adds the prompt's result to the create's answer as `relayFirstPrompt` (`first-prompt.mjs`). A client on another box saves the round trip it would spend between the answer and its own prompt; a client whose answer lacks the field sends the prompt itself.
- `GET /v1/host` returns the box's CPU, memory and memory groups (on Linux each leaf cgroup's anon, shmem and swap from memory.stat and memory.swap.current, with the file cache apart; on macOS the pressure feed) and its own `pi-pool queue --json` and `pi-pool config` unparsed, from `host-stats.ts`; Settings > Hosts draws one card per box from it.
- `POST /v1/watch` takes worker pids, one per line, and returns `{"usable":...,"footprints":...}`: the box's usability reading (the raw pressure feed on macOS, PSI, swap-outs and runnable tasks a core over the CPUs the relay may run on, on Linux, from `host-stats.ts`) and those workers' footprints from sieun-pi's `worker-footprint.py`, which the install copies beside the relay. The chat service's watch reads every other box this way, so the worker totals and each box's Agent sessions cover every box. When the helper fails or passes its 30 s kill, the answer keeps the reading with `"footprints":null` and the helper's error in `footprintsError`.
- `GET /v1/usable` returns the same usability reading alone. The chat service reads it beside `/v1/watch`, so a slow footprint helper on a loaded box never loses the reading.
- `GET /v1/file?path=<absolute path>` reads a file under the configured roots, by default `~/.prime/agent/sessions`, `~/.prime/agent/session-artifacts` and `~/.prime/agent/logs` (the daemon logs, so the chat host's resume pass sees this box's daemon restarts), and any other path gets 403. `Range: bytes=N-` returns 206 from offset N, `HEAD` returns the size, and a folder returns `{"entries":[...]}`.

## Install

Run `node components/prime-relay/install.mjs --ref <commit>` from a sieun-pi checkout on the box. It copies `relay.mjs`, `host-stats.ts`, `owner-turn.mjs`, `first-prompt.mjs` and `components/user-history/src/worker-footprint.py` from that commit to `~/.local/share/prime-relay`, writes `~/.config/prime-relay/relay.json` and a 0600 token file when they are missing, and restarts `prime-relay.service` (systemd user unit) on Linux or `com.sieun.prime-relay` (launchd) on macOS. The launchd job runs as `Interactive`, because launchd's default clamp left the relay at priority 20 on a loaded Mac and its footprint helper past the 30 s kill. The relay listens on the box's `tailscale ip -4` at port 7790 unless `--listen` or `--port` says otherwise.

The sieun-pi side lives in `components/user-history/src/hosts.ts`. It reads `~/.config/sieun-pi/hosts.json`, opens `~/.local/state/sieun-pi/hosts/<host>.sock` for every other host so `new DaemonClient(path)` reaches that host unchanged, and reads remote session files with `readHostFile`. `sieun-pi hosts list|start|read|transcript` drives the same code from a shell.

## Moving a chat to another box

Prime finds a stopped subagent through its per-box spawn ledger (`~/.prime/agent/rlm-ledger/<hash>.jsonl`), and a chat tree copied in from another box brings its children's files but no ledger edges, so the daemon answers `Unknown active session` for each of them. After the copy, run `python3 components/prime-relay/adopt-moved-subagents.py --apply` on the receiving box. It appends one spawn edge per child that has none, and it adds ` before move` to a child whose name the parent already gave to a fresh copy. Without `--apply` it only prints the edges, and a second run appends nothing.
