# Experience first

When implementation convenience conflicts with user delight, choose delight.

- Make every feature, control, and option earn its place, and say no to the rest.
- Ship three polished features before ten rough ones.
- Prototype a design in throwaway HTML before you build it in production code.
- Finish the details: transitions, alignment, spacing, feedback, and error states.
- Cut or hide any feature that does not serve the central workflow.

The user is whoever consumes the work. For a UI, that is the end user. For a library or internal API, it is the colleague who imports it. The engineer who maintains the code next is a user too. Explain the impact of a change from the user's seat.

`principle-foundational-thinking` decides the order of work. This principle decides the target.
